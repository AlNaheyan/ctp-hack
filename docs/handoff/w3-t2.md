# W3-T2 Native Messaging Handoff

- **Host name:** `com.ctphack.discussionnotch.bridge`
- **Template:** `native-host/manifest.template.json`
- **Generated manifest:** `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.ctphack.discussionnotch.bridge.json`
- **Register:** `npm run native:register -- <32-character-extension-id>`
- **Unregister:** `npm run native:unregister`
- **Extension ID assumption:** unpacked IDs are machine/path-specific; the
  registration command validates and installs exactly the ID copied from
  `chrome://extensions`. No manifest `key` is committed.
- **Extension state:** `transport.status` and
  `chrome.storage.session.nativeConnectionState` use `disconnected`,
  `connecting`, `connected`, or `error`; the transport also exposes
  `lastError` and `lastAcknowledgedAt`.
- **macOS state:** `NativePlaybackBridge.shared.connectionState` and
  `NativePlaybackBridge.shared.session` (`DiscussionSessionState`). W3-T3 can
  observe connection state/events; W3-T4 loads analysis into the same session.
- **Wire limit:** 8192 UTF-8 bytes. The host validates 4-byte little-endian
  framing, UTF-8, JSON, schema version/type, and playback bounds before calling
  `session.receive`.
- **Reconnect:** 250 ms exponential backoff capped at 10 seconds; a fresh MV3
  worker connects on first send.
- **Fallback:** none. The official Chrome native-messaging path is implemented;
  no loopback WebSocket or listening port is present.
- **Automated checks:** `npm test`, `npm run lint`, and on macOS
  `swift test --package-path Packages/NativeMessagingHost`.
- **Manual checks:** follow the restart checklist in `native-host/README.md` and
  verify player-to-app state latency remains below 500 ms.
