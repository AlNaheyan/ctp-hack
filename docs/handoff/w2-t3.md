# W2-T3 Integration Handoff

## Result

The Chrome extension now observes the active YouTube player across normal
playback and single-page navigation. It emits contract-valid playback state
immediately for important player events and every 250 ms only while playing.

## Message path

```text
YouTube <video>
  -> classic content script: PLAYBACK_OBSERVATION
  -> MV3 service worker: ordered envelope creation and validation
  -> replaceable transport: PLAYBACK_STATE v1
```

The content-to-worker payload contains `type`, diagnostic `reason`, and the raw
playback payload. `reason` is local diagnostics and is not added to the v1 wire
contract.

## Transport adapter

W3-T2 should replace only `createMockTransport()` with an implementation of the
existing interface:

```text
name
status
connect() -> Promise<void>
send(message) -> Promise<void>
disconnect() -> Promise<void>
onStatusChange(listener) -> unsubscribe
```

The forwarder reconnects whenever a fresh/restarted worker sees a disconnected
transport. It serializes asynchronous sends so observations cannot overtake one
another, and one failed send does not poison later messages.

## Observer lifecycle

- Immediate reasons: `injected`, `videochange`, `play`, `pause`, `seeked`,
  `ratechange`, and `loadedmetadata`.
- Playing cadence: 250 ms; there is no interval while paused or off a canonical
  YouTube video route.
- SPA signals: `yt-navigate-finish`, `popstate`, and player DOM replacement.
- Replaced/detached players lose every media listener and timer before the new
  player is attached.
- Re-injection disposes the previous controller, preventing duplicate listeners.
- A failed content-to-worker send receives one bounded retry after 250 ms.

## Permissions

The manifest requests only `https://www.youtube.com/*`. It requests no general
browser permission and specifically does not request `nativeMessaging`; W3-T2
owns that permission and the native-host installation.

The automated observer harness covers live cadence, pause, every immediate media
event, same-element SPA ID changes, player replacement and cleanup, feed-preview
suppression, worker-wake retry, reinjection, and contract normalization. The
forwarder suite covers first-message reconnect, ordering, validation, and
post-failure recovery without requiring Chrome or native messaging.
