# W4-T4 — Demo Script and Fallback Assets

- **Lane:** product/demo
- **Branch:** `work/w4-t4-demo-assets`
- **Estimate:** 2–4 hours
- **Depends on:** all Wave 3 packages

## Goal

Demonstrate the product clearly even when captions, Gemini, or the network is unreliable.

## Inputs

- Integrated app and mock API.
- Measured end-to-end behavior from W4-T1 as it becomes available.
- Canonical production contracts and fixtures.

## Work

- Select a short discussion with pre-reviewed insight moments.
- Prewarm a schema-valid 24-hour demo cache through the supported app path.
- Write a 2–3 minute script showing submit, ready, trigger, pause, speed change, and seek.
- Prepare a local mock-backend fallback using the same API contract.
- Capture architecture, privacy, latency, limitations, and next-step pitch evidence.
- Define presenter roles and component-specific recovery actions.

## Deliverables

- `docs/demo/` script, timestamp cue sheet, recovery notes, and fallback instructions.
- Contract-valid demo fixture/cache preparation procedure.
- Pitch evidence and concise limitations statement.

## Acceptance checks

- Live and clearly disclosed fallback paths are rehearsed.
- Expected cards and timestamps are listed.
- The pitch treats insights as fallible observations, not verdicts.
- No private transcript, secret, or API key appears in assets.

## Handoff to integration

Report primary/fallback runbooks, selected URLs and timestamps, presenter assignments, cache preparation, and recovery actions. Never add a hidden code bypass for demo mode.
